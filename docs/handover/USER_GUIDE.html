Personal AI OS — 사용 설명서

대상: 시스템 소유자(관리자 owner) · 기준일: 2026-11-04 · Dashboard 주소: http://127.0.0.1:8710

1. 이 시스템으로 할 수 있는 일

AI에게 코딩 맡기기Telegram으로 Hermes에게 말하면 Claude 또는 Codex가 지정한 프로젝트에서 작업하고 커밋까지 만듭니다.
변경 내용 검토·승인Dashboard에서 바뀐 코드(diff)를 보고 커밋을 승인하거나 거부합니다.
테스트 · 게시 준비승인한 커밋을 격리된 환경에서 실제로 테스트하고, 게시 가능 여부와 예정 브랜치·PR 내용을 확인합니다. (실제 GitHub 게시는 아직 꺼져 있습니다)
학습 관리배우고 싶은 분야·목표·로드맵을 관리하고, 버전별로 고치거나 되돌립니다. AI 초안은 설정 후 사용 가능합니다.
핵심 원칙: AI는 제안하고, 결정은 사람이 합니다. 승인·게시·로드맵 변경은 모두 화면에서 직접 확인하고 체크박스를 눌러야만 반영됩니다.

2. 시작하기 · 로그인

  1. 이 PC에서 브라우저로 http://127.0.0.1:8710에 접속합니다. (보안상 이 PC에서만 열립니다)
  2. 사용자 이름 owner, 비밀번호를 입력합니다. 초기 비밀번호는 D:\personal_ai\secrets\dashboard-admin.password에 있습니다. 비밀번호 관리자에 옮긴 뒤 이 파일은 지우는 것을 권장합니다.
  3. 로그인하면 왼쪽(모바일은 위쪽)에 메뉴가 나타납니다.

4. Hermes에게 작업 맡기기

Hermes는 Telegram에서 대화하는 AI 관리자입니다. 직접 코드를 고치지 않고, 요청을 정리해 Claude 또는 Codex에게 위임합니다.

이렇게 말해 보세요

  • "hello-world 프로젝트에 CONTRIBUTING.md 파일을 추가하는 작업을 Codex에게 맡겨줘."
  • "방금 맡긴 작업 상태 알려줘." · "결과 요약해줘." · "그 작업 취소해줘."
  • "등록된 프로젝트 목록 보여줘." · "시스템 상태 어때?"
  • "그 작업의 변경 내용 요약해줘." (Private 프로젝트의 코드 내용은 Hermes에 보여주지 않습니다)
Hermes는 승인·게시·GitHub 쓰기를 할 수 없습니다. "승인해줘"라고 해도 거절하고 Dashboard로 안내합니다. 이것은 의도된 안전장치입니다.

5. Overview

  • Controller / Hermes / Claude worker / Codex worker: 각 구성요소 상태. online은 최근 1분 안에 작업을 확인한 것, unknown은 아직 정보가 없는 것입니다.
  • Running / Queued / Completed / Failed / Awaiting approval: 작업 수와 승인 대기 리뷰 수.
  • Recent tasks: 최근 작업. 클릭하면 상세로 이동합니다.
  • Host resources: CPU·메모리 등은 아직 수집하지 않습니다(추후 기능).

6. Tasks

  • 위쪽 필터로 에이전트(claude/codex), 프로젝트, 상태를 골라 Filter를 누릅니다. 목록은 5초마다 자동 새로고침됩니다(체크 해제 가능).
  • 작업을 누르면 지시 내용, 결과/오류, 작업 브랜치, 기준 커밋, 결과 커밋, 소요 시간, 바뀐 파일이 보입니다. 커밋이 있으면 review → 링크로 검토 화면에 갑니다.
  • 대기 중이거나 실행 중인 작업은 Cancel task로 취소할 수 있습니다. 실행 중이면 Worker가 멈춘 것을 확인할 때까지 cancel_requested로 보입니다.

7. Projects

AI가 작업할 수 있는 프로젝트 목록입니다. 공개/비공개, 기본 브랜치, 허용 에이전트, 코드 수정 허용 여부, 사용 여부, 마지막 동기화와 오류가 보입니다. 이 화면에서는 바꿀 수 없습니다(관리자 API로만 변경). 인증 정보는 표시되지 않습니다.

8. Code Reviews · 커밋 승인

목록 위 탭에서 상태별(awaiting_approval, approved, rejected, invalidated, all)로 볼 수 있습니다. 검토할 항목을 누르세요.

검토 화면에서 확인할 것

  • Project · Agent · Base · Head · Tree: 어느 저장소의 어떤 커밋인지.
  • Tests: 격리된 Test Runner의 결과. passed이면 이 커밋에서 승인된 테스트가 모두 통과한 것입니다.
  • Commit message, 파일별 변경 내용(diff, 추가 + / 삭제 −).
  • 경고 상자: 잘린 diff, 바이너리 파일, 민감 파일(키·토큰 의심) 숨김, 대상 커밋 변경, 테스트 없음 등. 경고가 있으면 승인 전에 꼭 읽으세요.

승인 또는 거부하기

  1. Approve… 또는 Reject…를 누릅니다.
  2. 확인 단계에 프로젝트, Base/Head SHA, 파일 목록이 다시 나옵니다. 확인했으면 체크박스를 선택합니다. 필요하면 사유를 적습니다.
  3. Approve commit / Reject commit을 누르면 리뷰 화면으로 돌아와 결과가 표시됩니다.
승인은 "이 정확한 커밋을 검토했다"는 기록입니다. GitHub에 올라가지 않습니다. 이미 처리된 리뷰를 다시 승인하거나, 그 사이 커밋이 바뀌었으면 "Not recorded … (409)" 안내가 나오고 아무 것도 바뀌지 않습니다.

9. Publishing — 게시 준비

Code Review 화면 아래의 Publishing 패널입니다. 게시까지는 단계가 나뉘어 있습니다.

리뷰 승인→Run tests (자동 또는 수동)→Validate / Dry-run→Authorize publishing…→Publish (현재 비활성)

Test validation

  • 프로젝트에 등록된 테스트 명령을 이 커밋 그대로 격리 환경에서 실행한 결과입니다. 명령, 종료 코드(exit code), 결과가 표로 나옵니다.
  • 결과가 없으면 "게시 불가 — 이 커밋에 연결된 테스트 실행 결과가 없습니다."가 표시됩니다. Run tests로 실행하세요.
  • AI가 "테스트 통과했어요"라고 말한 것은 결과로 인정하지 않습니다. 실제 실행 결과만 인정됩니다.

Validate / Dry-run

Publisher가 커밋·파일·작성자·테스트·원격 저장소 상태를 독립적으로 검사하고, Eligibility(적격 여부)와 Reason(막힌 이유)을 보여줍니다. 예정 브랜치(personal-ai/<작업 ID>)와 예정 PR 내용도 보입니다. 아무 것도 게시되지 않습니다.

게시 승인 (Authorize publishing…)

리뷰 승인과 별개인 두 번째 승인입니다. 리뷰 승인 + 테스트 통과 + 최근(30분 이내) 적격 dry-run이 있을 때만 버튼이 나타납니다. 확인 화면에서 저장소·브랜치·커밋·파일·테스트·작성자를 다시 보고 체크박스를 선택해야 합니다. 승인은 30분 뒤 만료됩니다.

10. Learning 시작하기

메뉴의 Learning을 누르면 학습 Overview가 열립니다. 순서는 분야 → 목표 → 로드맵입니다.

  1. Domains 아래 폼에서 분야를 추가합니다(예: Frontend). 상위 분야를 고르면 하위 분야가 됩니다. 상태는 exploring, planned, active, paused, maintaining, archived 중 하나이며, 표의 Save로 바꿉니다. 삭제 대신 archived로 보관합니다.
  2. Goals에서 목표를 추가합니다. 목표 수준(0–4), 주간 학습 시간(분), Deadline을 넣을 수 있습니다. Deadline은 당신이 정한 고정값이며 AI가 바꾸지 않습니다.
  3. Roadmaps에서 목표를 골라 로드맵을 만듭니다. 만들면 바로 로드맵 화면으로 이동합니다.
Overview의 진행률·숙련도·학습 시간·오늘의 계획은 아직 N/A로 표시됩니다. 과제·평가·일정 기능(L2/L3)이 생기면 채워집니다. 서로 다른 지표라 하나의 점수로 합치지 않습니다.

11. 로드맵 만들기 · 편집

구성

  • 노드: stage(단계), topic(주제), skill(기술), milestone(이정표). 노드마다 제목, 설명, 예상 시간(분), 상위 노드, 기술 이름, 참고 자료를 가질 수 있습니다.
  • 선수지식 연결: "A를 알아야 B를 배울 수 있다"는 관계. 화면에서는 각 노드 옆에 requires: …로 보입니다. 순환(A→B→A)은 허용되지 않습니다.
  • 같은 기술 이름(예: React Hooks)은 여러 로드맵에서 하나의 기술로 공유됩니다.

직접 편집하기

  1. 로드맵 화면의 Edit content (JSON)…을 누릅니다. 현재 내용(처음이면 예시)이 편집 창에 나옵니다.
  2. 내용을 고치고 Propose changes를 누릅니다. 바로 반영되지 않고 제안이 만들어집니다.
  3. 제안 화면에서 추가(+), 삭제(−), 변경(~)된 노드와 연결, 예상 시간 변화를 확인합니다.
  4. 체크박스를 선택하고 Approve as new version을 누르면 새 버전이 됩니다. 마음에 들지 않으면 Reject proposal.

버전과 되돌리기

Versions 표에 모든 버전이 남습니다. 예전 버전 줄에서 체크박스를 선택하고 Restore를 누르면 그 내용으로 새 버전이 만들어집니다(기존 기록은 지워지지 않음).

"그 사이 로드맵이 바뀌었습니다" 안내가 나오면, 다른 승인이 먼저 반영된 것입니다. 현재 버전을 보고 다시 제안하세요. 순환이 있으면 순환 경로(예: hooks → jsx → hooks)를 알려줍니다.

12. AI 초안

로드맵 화면의 AI draft 상자에서 현재 수준, 주간 시간, 메모를 적고 Draft a roadmap(또는 Draft a revision)을 누르면 AI가 초안을 제안으로 만듭니다. 직접 편집과 똑같이 차이를 보고 승인해야 반영됩니다.

  • AI가 추천한 참고 자료에는 AI 제안 · 미검증이 붙습니다. 실제로 있는지 확인하고 쓰세요.
  • AI 출력이 형식에 맞지 않거나 순환이 있으면 invalid 제안이 되고, 로드맵은 바뀌지 않습니다.
  • 월 비용 상한을 넘을 것 같으면 실행 전에 거부됩니다. 이번 달 사용액은 Learning Overview의 AI drafts 카드에 표시됩니다.
현재 상태: AI 초안은 아직 꺼져 있습니다. 버튼이 비활성화되어 있고 Overview에 "not configured"와 빠진 설정이 보입니다. 켜려면 secrets\learning.env에 제공자·모델·월 상한·단가를, secrets\learning-ai.key에 API 키를 넣고 Learning 서비스를 다시 시작하면 됩니다(관리자 작업).

13. Idea Inbox

  • Learning Overview의 Quick idea 또는 Idea Inbox 화면에서 한 줄로 아이디어를 기록합니다. 분야와 우선순위를 붙일 수 있습니다.
  • 아이디어를 적어도 일정이나 로드맵에 자동으로 들어가지 않습니다. 생각나는 대로 모아 두세요.
  • 검색창으로 찾고, 각 줄에서 내용·분야·우선순위·상태(inbox, triaged, promoted, archived)를 바꿉니다. archived는 기본 목록에서 숨겨집니다(상태 필터로 다시 볼 수 있음).

16. 자주 묻는 질문 · 문제 해결

"Security check failed" 또는 로그인 화면으로 돌아갔어요

세션이 만료되었거나 Dashboard가 다시 시작된 것입니다. 페이지를 새로고침하고 다시 로그인한 뒤 같은 작업을 반복하세요. 다른 탭의 오래된 화면에서 제출해도 같은 안내가 나옵니다.

"Too many attempts"로 로그인이 안 돼요
